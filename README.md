# gingerbad_sound_manager

This asset is composed of two scripts ("SoundObject.cs", "SoundScript.cs") and their auxilliary code:

## SoundObject.cs

Generates a gameObject containing a "SoundScript" and its audioSource on runtime. Some fields are directly parsed ("audioClip", "outputMixer", "audioPriority", "loopAudio"), others were implemented for additional logic:

| Argument | Type | Required | Default | Description |
|----------|------|----------|---------|-------------|
| `ignoreTimescale` | Bool | ✓ | F | If false, the pitch is dynamically scaled with the value of the timescale |
| `baseVolume` | Float | ✓ | `0` | Scaled volume of the clip to be played |
| `randomVolume` | Float | No | `0` | The volume becomes baseVolume + ] - randomVolume/2, baseVolume + randomVolume/2] |

"settings3D" - This field allows instantiating the gameObject as a copy of a prefab. This prefab is required to have at leastan audioSource component for proper functioning. The fields which are included in the "Sound" will be overwritten but all the other ones will be kept. The idea was that this logic would allow easily including consistent 3D settings across different sounds (shown in the sample scene). In practice this field can also be used to instantiate the audioSource as part of a complex object, albeit this might require additional logic. Leave this field empty to generate 2D sounds.

"dynamicVolume" - This field uses auxiliary code "FloatVariable" to allow for dynamic updates to the volume of the audioSources after they have been instantiated. This is useful, for example, if you wish to allow the player to change the in-game volume. You can also leave this field empty to ignore this logic.

"baseVolume/randomVolume" - The baseVolume is used as the center of an uniform distribution with the interval . Bear in mind that Unity clips the volume between 0 and 1.

"basePitch/randomPitch" - Same logic as the "baseVolume/randomVolume", except Unity only clips the pitch at 0.

SoundScript - A script generated by the sound object in runtime which handles the dynamic volume and pitch changes, as well as the logic to destroy the  generated gameObject once its audioSource finishes playing. Non-looping sounds are destroyed automatically. Looping sounds have to be destroyed from external calls (stopped from script, destroyed from script, destroyed with parent).

To play an audio clip create a SoundObject from the Unity asset menu and fill its fields to your liking. Then you can import this object to any script and call Play() to generate audio at runtime. The Play() function accepts two optional parameters:

Transform parent: the generated gameObject is set as a child of the given parent.

Vector3 spawnPosition: the position in which to spawn the gameObject. If left as null, the gameObject will either be spawned at parent.position or at [0,0,0] if no parent is given.

The Play() function returns a gameObject containing an audioSource and a SoundScript.

The PlayFromUI() function is a wrapper that allows calls from UI elements.

For a practical example on how to use this this asset, please check the sample scene and the resources available there.

## Scripts

### `train.py`

Trains the model on the provided dataset.

#### Arguments

| Argument | Type | Required | Default | Description |
|----------|------|----------|---------|-------------|
| `--data` | Path | ✓ | – | Path to the dataset |
| `--epochs` | int | No | `100` | Number of training epochs |
| `--batch-size` | int | No | `32` | Batch size |

**Example**

```bash
python train.py --data dataset/ --epochs 50
```

---

### `evaluate.py`

Evaluates a trained model.

#### Arguments

| Argument | Type | Required | Default | Description |
|----------|------|----------|---------|-------------|
| `--model` | Path | ✓ | – | Path to trained model |
| `--test-set` | Path | ✓ | – | Test dataset |
| `--output` | Path | No | `results.json` | Output file |

**Example**

```bash
python evaluate.py --model model.pt --test-set test/
```
